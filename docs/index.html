The language LLMs write well.

OpenS is a high-level, multi-paradigm language for building AI software — agents, MCP servers and clients, LLM pipelines — designed so models produce correct code on the first try, and compiled to web, mobile and native.

Why OpenS

One language, three paradigms, with LLMs and portability as first-class goals.

🧩

Multi-paradigm

Functional (closures, first-class functions, immutability, |>), imperative (var, loops, unsafe) and object-oriented (type + impl, trait). They combine — no separate modes.

🤖

LLM-first

Tools, MCP servers and typed prompts are built in. llm.ask<T> generates a JSON Schema from T, requests structured output and validates it.

⚙️

C++-style memory

Explicit, tiered: values, checked references &T / &var T, heap box T, and raw pointers *T confined to unsafe.

📐

Explicit over implicit

No implicit conversions, no surprise null, no invisible exceptions. Effects are declared with uses, so a signature tells you what a function can do.

🛠️

Fixable diagnostics

Every compiler error has a stable code, an exact location and, when possible, an automatic fix — in human text and in JSON, so an agent can read, fix and recompile.

🌐

Portable by design

One dependency-free frontend targets TypeScript (Node/Deno/Bun, MCP), WebAssembly (browser, edge), native (Cranelift/LLVM) and mobile (iOS/Android via FFI).

A taste of OpenS

A web page summarizer exposed as an MCP tool.

/// Summarizes a web page with an LLM.
tool summarize_url(url: Url) -> Result<Summary, Error>
  uses net, llm
{
  let page = await http.get(url)?;
  let r = await llm.ask<Summary>(summarize(page.text))?;
  return ok(r);
}

server Summarizer {
  expose summarize_url
}

Statements end in ;; block constructs (if, while, for, match, unsafe) end in }.

Roadmap

Where the compiler is and where it's going.

  1. Lexer, stable error codes, JSON output, opens fix done
  2. Parser + AST + error recovery; multi-paradigm & memory syntax done
  3. Type checking, Result, local inference, capabilities next
  4. TypeScript backend: tool / server → a real MCP server
  5. ask<T>, prompt, mocks & traces; opens test
  6. LSP for VS Code + official formatter
  7. WebAssembly backend + web playground
  8. Native backend (Cranelift) + C/C++ FFI
  9. Mobile bindings (iOS / Android)

Get started

Requires Rust. File extension: .ops.

# run the tests
cargo test # check a file (lexing + syntax)
cargo run -- check examples/contador.ops # print the AST
cargo run -- parse examples/contador.ops # apply automatic fixes
cargo run -- fix examples/errores.ops # explain an error code
cargo run -- explain E0208
